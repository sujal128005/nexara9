01

Overview

PixelProof generates, validates and scores visual-reasoning tasks from real operational settings: reading industrial gauges, business charts and wiring diagrams, where one misread value leads to a wrong decision.

Every answer is re-derived from the pixels by an independent verifier, and every task ships with a “counterfactual twin” that differs in one decisive detail. Same question, different correct answer, so a model that guesses from the text alone scores zero.

02

Problem and aim

The problem

Many visual benchmarks can be partly solved without looking at the image, and some answers in them are simply wrong. That makes it hard to know what a vision model can really see.

The aim

A reusable, reproducible pipeline that proves every question needs the image and every answer is correct.

03

How it works

Step through it. Use the tabs, or the arrow keys once a tab is focused.

Step 1 of 6

Sample and render

A scene is sampled from one of six families (gauge, chart, wires, count, spatial, maze) at a chosen difficulty, and drawn.

Step 2 of 6

G1 · Evidence

The image must carry enough evidence: readable tick spacing, clear bar gaps, wide wire crossings, no hidden objects.

Step 3 of 6

G2 · Verifier

An independent algorithm recomputes the answer from the pixels. If it disagrees with the generator, the task is rejected.

Step 4 of 6

G3 · Twin

One minimal edit (a needle, a bar, two swapped wire ends) must change the answer while the question stays identical.

Step 5 of 6

G4 · Dedup

A perceptual-hash check removes near-duplicate images.

Step 6 of 6

Evaluate

Models are scored strictly: no multiple choice, explicit tolerances, pair accuracy and an error taxonomy, in a self-contained HTML report.

04

Architecture

How the pieces fit together, from what you see to where the data lives.

The journey of one request

  1. pixelproof generate samples scenes, renders them and runs each through four gates.
  2. Accepted tasks go to tasks.jsonl with images and a manifest of the seed and rejections.
  3. pixelproof eval queries a model over HTTPS, with caching and a call budget.
  4. pixelproof report writes a self-contained HTML report; frontier finds breaking levels.

06

Methodology

  1. Generate tasks from a seed, so any dataset can be reproduced exactly.

  2. Validate every task through four gates before it is used.

  3. Run text-only controls to prove the image is required.

  4. Search adaptively for the difficulty level where each model breaks.

Learn the concepts

The ideas this project is built on, in plain words.

What is a vision-language model?

An AI model that takes an image and text together and answers in text, for example “what does this gauge read?”.

What is a counterfactual twin?

A second version of the same task with one decisive change, so the correct answer changes but the question does not. Getting both right is strong evidence the model really looked.

Why “pair accuracy” as the headline?

A model can get one twin right by luck or by guessing a common value. Requiring both twins to be right removes most of that luck.

What is a text-only control?

The same model, or a smart guesser, given the question without the image. If it scores well, the benchmark is leaking answers through the text.
