01

Overview

“Every AI answer has sources. Now every source gets paid.” PayPal Attribute is an attribution and payout rail for agentic commerce. A shopping agent cites the reviews, guides and videos that shaped its answer; the citations travel inside the PayPal order; when the payment is captured, AI scores how much each source influenced the purchase, risk checks remove fraud, and the commission is split and paid to creators through PayPal Payouts.

It is a hackathon prototype, not an official PayPal product, and runs in the PayPal sandbox where no real money moves.

02

Problem and aim

Problem

When an AI agent gives a single answer, there are no clicks and no affiliate links. Creators whose work made the answer trustworthy lose the income that funds them, and merchants cannot see what drove a sale.

Aim

Make AI recommendations pay the people behind them, fairly and safely, using rails PayPal already has.

03

How it works

01 / 05

Ask the agent

A shopper asks what to buy. Retrieval runs in code; the model writes a grounded answer where every claim has a footnote to a real creator source.

02 / 05

Token in the order

An attribution token rides inside the PayPal order (custom_id) and is verified when the payment is captured.

03 / 05

Score influence

AI scores how much each cited source influenced the purchase, blended 75/25 with a deterministic baseline so one model answer cannot swing payouts.

04 / 05

Risk checks

Six checks on every sale: self-dealing, blocked sources, citation stuffing, merchant budget, purchase velocity and the attribution window.

05 / 05

Split and pay

The commission minus a 10% network fee is split by influence, held through the return window, then paid via PayPal Payouts. Refunds reverse or claw back payouts.

04

Architecture

Request flow

  1. The agent answers with citations; an attribution token is created for them.
  2. Checkout creates a PayPal order carrying the token in custom_id.
  3. On capture (and the verified webhook), influence is scored and risk checks run.
  4. The pool is split to the cent and held; releaseDuePayouts() pays via PayPal Payouts.

06

Methodology

  1. Keep money in integer cents and write every movement to an append-only ledger.
  2. Round shares with the largest-remainder method so payouts always add up exactly.
  3. Use a fallback chain of free models (Groq, then Gemini, then built-in rules) so the product works with no keys at all.
  4. Seed 30 days of history by running the real engine on simulated orders.

Concepts

01What is attribution?

Working out which sources caused a sale. Affiliate links do it with clicks; here the AI’s own citations are the evidence.

02Why store money in cents?

Decimal fractions cannot be stored exactly in floating point, so totals drift. Whole numbers of cents never do.

03What is largest-remainder rounding?

Give everyone the rounded-down amount, then hand the leftover cents one by one to whoever had the biggest fractions. The shares always add up to the exact pool.

04Why a hold window?

Buyers can return products. Waiting until the return window closes means creators are not paid for sales that get refunded.
