A student dashboard for schools and colleges: AI question papers, syllabus tracking, past papers, notes, branch channels and a code editor.

01

Overview

NexGen brings everything a student needs into one place. Students can generate practice question papers, follow their syllabus, search past-year papers, share and download notes, talk in branch channels and write code, all from a single dashboard.

This repository is the high-fidelity front-end prototype, designed in a glassmorphism style with dark and light modes.

02

Problem and aim

Problem

Study material is scattered across WhatsApp groups, drives and notice boards. Students spend more time finding resources than using them.

Aim

One academic home for every student in a school or college, with AI tools that save real study time.

03

How it works

01 / 06

Dashboard

A gamified home with progress, study-intensity heatmaps and streaks, around a CSS-only 3D “knowledge core”.

02 / 06

AI paper generator

Choose topic, difficulty and question type to generate a mock exam, preview it on an A4 sheet and download it as a PDF.

03 / 06

Syllabus tracker

Add courses, tick off topics as you finish them and watch module progress bars fill up.

04 / 06

Past papers and notes

A searchable archive of past-year questions, and a notes library where students upload and download material.

05 / 06

Branch channels

Discord-style chat rooms, with channels locked to each branch (CSE, ECE and so on).

06 / 06

Code editor

A lightweight in-browser editor for Python, JavaScript, C++ and Java with a console and a team chat panel.

04

Architecture

Request flow

  1. Each module is a self-contained page with its own HTML, CSS and JavaScript.
  2. Pages share a visual language and the theme setting through the browser’s storage.
  3. Interactions such as paper generation, uploads and chat are simulated in the browser today.
  4. The roadmap connects them to a Node.js API, the Gemini API and live chat.

06

Methodology

  1. Map a student’s week and the tools they jump between.
  2. Design every module as its own page with a shared visual language and an AI helper on each page.
  3. Build a high-fidelity prototype first, to test the experience before investing in a backend.
  4. Plan the backend next: Node.js and Express, real AI through the Gemini API, Firebase sign-in and live collaboration over WebSockets.

Concepts

01What is a high-fidelity prototype?

A version that looks and feels like the real product but is not wired to a real backend yet. It lets you test the experience with users cheaply, before building the expensive parts.

02How can a web page make a PDF without a server?

Libraries like html2pdf.js render the page section to a canvas and package it as a PDF entirely in the browser, so nothing is uploaded.

03How does the theme stay the same across pages?

The chosen theme is saved in the browser’s localStorage and read back on every page load.

04What is glassmorphism?

A visual style with frosted, semi-transparent panels (CSS backdrop-filter: blur) layered over colourful backgrounds.
